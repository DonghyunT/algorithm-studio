# 수행평가 작성 경험과 문항 개편 검토서

작성일: 2026-09-13. 작업 브랜치: `codex/assessment-guided-workspace`. 기준 커밋: `432a4fd` (이전 작업 공간 UI 보완 포함).

## 변경 목적과 결과

학생이 배운 범위의 문항을 풀고, 익숙한 실습 편집기로 자기 알고리즘을 설계하도록 바꿨습니다. 미응답 때문에 다음 파트로 이동하지 못하는 제한은 두지 않았습니다. 수동 제출은 Part 3 방문 후 가능하며, 시간 만료와 교사 종료에 따른 자동 제출은 이 제한을 적용하지 않습니다.

| 영역 | 변경 |
|---|---|
| 객관식 | 보기의 영어 병기 제거, 정답을 암시하던 제목을 문제 번호로 변경 |
| 단답형 | 5번은 30℃ 이상일 때 선풍기를 켜는 선택 결과, 6번은 컵 3개를 하나씩 씻는 반복 횟수로 교체 |
| 자연어 설계 | 빈 현재·목표 상태 안내와 순차·선택·반복 카드, 위/아래 순서 이동 제공 |
| 순서도 작성 | 나만의 백지 편집기를 공유하고 세로 기호 드래그·연결·이동·정렬·접기 유지 |
| 평가 도움 | AI·완성 풀이·예시·외부 공유 제외, 실행 과정과 확인 가능한 오류 사실 유지 |
| 이동·제출 | 모든 파트 하단 이동, 응답 개수 안내, Part 3 방문 이후 수동 제출, 저장 실패 재시도 |

30분, 객관식 30점·단답형 30점·Part 3 40점을 유지합니다. 세 구조를 모두 쓰거나 추가 성찰 문장을 작성하도록 요구하지 않습니다.

## 구현과 자료 보존

`assessment-workspace.js`는 기존 실습 DOM을 평가 영역으로 옮기고 서로 다른 작업 상태를 교체합니다. 평가 진입 전 실습 초안을 저장하며 평가 중 실습 자동 저장은 중지합니다. 평가 이탈 시 실습의 카드·그래프·화면 위치·패널 설정을 복원합니다. 평가 전용으로 중복 구현했던 캔버스 코드는 제거했습니다.

구조화한 카드는 평가 답안의 `part3.plan.steps`에 저장합니다. 기존 텍스트 단계도 읽으며 교사 검토 화면에는 조건과 분기 행동을 구분하여 표시합니다. 현재 파트·Part 3 방문 기록은 세션 초안에 보존하고 재시험 초기화 시 지웁니다.

새로 준비한 회차에는 `questionVersion: 2`를 기록합니다. 버전이 없던 기존 회차는 버전 1로 취급하므로 기존 학생의 단답형 답안을 새 문항으로 재해석하지 않습니다. 교사 참고 점수는 회차의 버전으로 계산하며 학생 답안의 버전 변경으로 채점 기준이 바뀌지 않도록 했습니다. 기존 평가를 다시 시작하거나 재시험을 허용하는 것만으로는 문항 버전이 바뀌지 않습니다.

평가 실행은 기존의 제한된 문항별 검사기를 사용합니다. 실행 단계와 입력별 예상/실제 결과를 공통 패널에 표시하되 모든 자연어를 실행하는 엔진으로 확대하지 않았습니다. 해석 불가는 교사 검토 대상이며 자동 참고 점수를 확정 성적으로 표현하지 않습니다.

## 선생님 확인 방법

1. 로컬 미리보기 `http://127.0.0.1:4173/index.html?demo=1`을 새로고침합니다.
2. 교사용 화면에서 **새 평가 준비**로 새 회차를 만들고 학생으로 입장한 뒤 평가를 시작합니다. 기존 회차를 이어서 열면 자료 보존을 위해 이전 문항이 표시됩니다.
3. Part 1을 비워 둔 채 하단 다음 버튼으로 이동하고, Part 3 방문 전후 최종 제출 버튼을 비교합니다.
4. Part 3에서 빈 처방전과 세 종류의 카드를 작성하고 순서도를 조립합니다. 실행 패널을 펼쳐 진행 내용을 확인한 뒤 새로고침하여 답안 복원을 확인합니다.
5. 교사용 답안 화면에서 자연어 카드의 조건·행동이 읽기 좋게 구분되는지 확인합니다.

이번 작업은 로컬 구현·검증·커밋 범위입니다. 원격 푸시·main 병합·Vercel 배포·운영 DB 변경은 진행하지 않았습니다.
