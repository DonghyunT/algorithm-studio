# 구현 검토서

2026-09-12 · 개발 브랜치 `codex/classroom-reliability` · 원본 기준 `cacfc5e` · 검증 대상 제품 커밋 `2efed5e`. 최초 제품 구현 `638d327` 이후 평가 설계·화면 개선을 포함합니다.

별도 브랜치에서 구현·검증한 실습·평가 정책과 신뢰성 보완을 사용자 승인으로 로컬 main에 병합했습니다. 프런트엔드는 Vanilla JS이며 별도 번들 빌드가 없습니다. 이 문서는 운영 배포 승인이나 실제 성적 처리의 준비 완료 선언이 아닙니다.

## 검토할 동작

1. 실습: AI 검사에 실패하거나 AI가 응답하지 않아도 현재 상태로 결과물을 내보낼 수 있습니다. AI 의견은 합격 인증이 아니며 수정하면 이전 확인 상태가 무효화됩니다.
2. 평가: 끊긴 연결과 실행 중단 위치를 표시하고, 실행된 경우 입력별 예상/실제 결과를 비교합니다. 수정 방법과 정답 블록은 알려주지 않습니다. 검사 실패·미완성도 제출할 수 있습니다.
3. 저장: 서버 저장 확인 후 제출 완료로 바뀝니다. 실패하면 답안을 유지하고 재시도합니다. 응답을 잃은 뒤 같은 답안을 재제출하는 경우 이미 저장된 제출을 확인합니다. 새로고침 시 같은 탭·같은 인증의 평가/실습 초안을 복원합니다.
4. 교사: Google 로그인과 등록된 교사 역할이 필요합니다. 학생은 익명 인증으로 자기 기록에 접근합니다. 학생 점수를 믿지 않고 교사 화면에서 답안을 다시 계산합니다. 답안의 기호·연결 내용을 확인하고 0~100 범위에서 조정할 수 있습니다.
5. 화면: 겹치는 화면을 숨기고, 툴바가 줄을 나누어 모든 동작을 표시하도록 했습니다. 좁은 화면의 캔버스 높이 0 문제를 수정했습니다.
6. 평가 설계: 기존 완성된 레시피를 문제 상황·입력·요구 결과로 바꾸었습니다. 학생이 현재·목표 상태와 자연어 단계를 직접 작성하고 순서도를 조립합니다. 처방전은 저장·복원 및 교사 검토에 포함되지만 별도 점수·필수 단계 수·제출 조건은 추가하지 않습니다. 시간은 기존 30분, 총점은 100점입니다.
7. 평가 동선: 시작부터 제출 저장 성공까지 다른 코스·교사 화면·전체 메뉴 이동을 차단합니다. 새로고침 시 같은 탭의 평가로 복귀하며 저장 실패 시 잠금이 유지됩니다. 앱 외부 이동을 막는 시험 전용 브라우저 기능은 아닙니다.
8. 읽기와 작업 공간: 개념·퀴즈·학습 지도는 최대 1,200px로 중앙 정렬합니다. 실습은 넓은 작업 공간을 유지합니다. 평가 Part 3은 접을 수 있는 문제 안내·처방전과 캔버스의 두 영역, 가로 기호 도구 모음, 캔버스 아래 실행 결과로 구성합니다.

추가 성찰 문장, 힌트 사용 감점, 프레임워크 전환을 도입하지 않았습니다. 단원 과제 자동 취합은 연결되지 않은 상태임을 표시하고 가짜 학생 기록을 제거했습니다. 외부 게시판에 이미지/텍스트로 제출하는 경로를 안내합니다.

## 실행과 검증

개발용 Node 24에서 실행합니다.

```powershell
node tools/check.cjs
node --test --test-isolation=none tests/core.test.cjs tests/api.test.cjs
node tests/browser.cjs
node tools/preview.cjs
```

브라우저 검사는 Playwright와 Edge를 사용합니다. 다른 PC는 `PLAYWRIGHT_MODULE`, `BROWSER_EXE` 환경변수로 경로를 지정합니다. 로컬 미리보기는 `http://127.0.0.1:4173/`입니다. `?demo=1` 시연 모드는 localhost에서만 활성화되며 교사 로그인과 DB를 대신하는 두 탭 시연입니다. 실제 인증 검증으로 해석하면 안 됩니다.

- 구문/로컬 파일 참조 검사 통과.
- Node 테스트 9개 통과: 네 문항 실행, 경계 조건·분기 반전·끊긴 그래프 거부, 악성/잘못된 입력, 수식, 기본 배점, 저장 실패/중복 제출, 토큰 서명·만료, API 인증·본문·모델·횟수 제한.
- Edge 브라우저 시나리오 18개 통과: 화면 전환, 한글 변수, 검사 무효화, 이름 HTML 주입 방어, AI 장애, 누락 분기, 샌드위치 초기화, 실습/퀴즈 복원, 두 탭 시작·마감, 평가 복원·저장 실패·재제출, 평가 하이라이트, 1920/1440/1366/1024/768px 캔버스. 추가로 읽기 화면 중앙 정렬, 평가 중 이동 잠금, 학생 처방전 작성·재배열·저장·교사 조회, 1440/1024/768px 평가 기호 버튼 배치와 스크롤 후 블록 드래그를 검사합니다. 브라우저 실행 오류와 콘솔 오류는 없었습니다.
- 브라우저 결과: [기록](../tests/results/browser.json), [평가 화면](../tests/results/assessment.png), [1366px 작업 화면](../tests/results/studio-1366.png).
- Firebase `deploy --only firestore:rules --dry-run` 컴파일 통과. 규칙 배포·학생 데이터 변경은 하지 않았습니다. 규칙의 런타임 허용/거부 시험은 별도로 필요합니다.
- GitHub PR/브랜치 push 시 구문·Node 테스트를 실행하는 CI 파일과 PR 양식을 추가했습니다. 원격에서 CI를 실행한 것은 아닙니다.

테스트의 Firebase·AI 통신은 모의 응답/차단 상태입니다. 실제 AI 비용과 운영 DB 저장을 발생시키지 않았습니다.

## 운영 배포 전에 남은 작업

[운영 준비 절차](OPERATIONS.md)를 따릅니다. Preview가 운영 DB와 자동 분리되지는 않으므로 현재는 로컬 시연을 검토 대상으로 제공합니다. 로컬 main 병합은 사용자 승인으로 완료했습니다. 원격 push, Vercel 새 배포, Firebase 규칙 적용은 하지 않았습니다.

검사 입력을 통과하는 것은 전체 풀이 정답의 증명이 아닙니다. 특히 네 평가 테마의 부분점수, 문장 표현 허용 범위, 검사 입력 공개 범위를 교사가 확인해야 합니다. 학생 화면에서 숨기는 AI 제한은 서버에서 평가 참여 여부를 확인하는 제한과 다르므로, 평가 보안을 완성했다고 주장하지 않습니다.
