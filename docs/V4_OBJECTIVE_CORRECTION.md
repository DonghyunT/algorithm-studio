# V4 단답형 인정 답안 확대와 성적 정정

2026-09-24 교사 최종 검토·병합·배포 승인에 따라 운영 은행 교체와 Firestore 정정을 완료했다. PR #9, main 병합 `a7facd9`. [배포 기록](DEPLOYMENT.md)에 코드·배포·검증 근거를 남겼다.

교사 재검토에 따라 일부 추가 표현과 동일 의미 변형을 제외하고 비공개 수정본·정정 계획을 재생성했다. 이전 계획의 해시는 사용하지 않는다. 실제 인정 목록, 운영 자료에서 도출한 규모와 계획 식별자는 Git 제외 비공개 자료에서만 관리한다.

## 승인 범위와 영향

- 교사 요청: 종료된 V4 전체(현재·보관 회차)를 비교하고 의미가 같은 표현을 추가 인정한다. 알고리즘·기호 명칭은 공식 용어 원칙을 유지하되 교사가 명시한 예외와 기존 허용답은 보존한다. 실제 인정 표현 목록은 비공개다.
- 운영 은행의 단답형을 모두 검토해 동등 표현을 추가하고 교사가 제외한 표현은 인정 목록에서 제거했다. 기존 정답, 문항 본문·ID·보기·배점·난이도·순서·배정 비밀값은 유지한다. 전체 문자열 비교를 유지하며 부분 문자열·숫자 추출·AI 유사도로 판정하지 않는다.
- 종료된 V4 현재·보관 회차를 읽기 전용으로 비교했다. 실제 학생별 결과와 영향 규모는 비공개 검토 자료에서 확인한다. 개인 식별 자료, 답안과 운영 자료에서 도출한 통계는 공개 문서에 남기지 않는다.
- 기존 답안과 Part 3 교사 확정/AI 제안은 보존한다. 저장된 점수가 계산 기준과 다르거나 전체 수동 조정/확정 점수가 있으면 자동 정정을 거부한다. 이미 내보낸 성적표 파일이나 외부 성적 시스템은 자동 갱신되지 않는다.

## 구현과 보호 장치

- `server/evaluation-bank.cjs`: 문항당 허용답 상한을 12에서 32로 확대. 채점 규칙과 배정 알고리즘은 유지한다.
- `server/objective-regrade.cjs`: 은행의 정답 추가만 허용하고 종료 V4·제출·회차 일치·알려진 문항·영역 중복을 확인한다. 점수 하락, 기존 저장 점수와 기준 불일치, 전체 확정 점수는 자동 정정하지 않는다. 비교는 저장된 응답 ID를 기준으로 하며 과거 배정 비밀값/은행 전체를 복원하는 기능은 아니다.
- `tools/apply-objective-regrade.cjs`: 승인된 계획의 해시를 확인하고 학급별 트랜잭션으로 원본 스냅샷과 변경 사유를 `archives`에 추가한다. 현재 학생 문서는 `scores`와 `objectiveCorrection`만 갱신한다. 답안·Part 3·교사 검토는 건드리지 않는다. 미리보기 이후 세션/학생이 바뀌면 중단하고 동일 계획 재실행은 중복 적용하지 않는다.
- 정정 감사 기록은 `kind: objective-regrade`, 복구 기록은 `kind: objective-regrade-restore`로 기존 회차 목록에서 제외한다. 기존 보관 문서나 Firestore 접근 규칙은 변경하지 않는다. 보관 답안에서 변경 대상이 생기는 다른 계획은 별도 검토를 요구하며 현재 도구로 적용하지 않는다.
- `objectiveCorrection`은 회차·제출 시각·객관식/단답형 답안에 묶인다. 향후 새 회차 시작으로 정정된 학생 자료가 보관되면 보관 상세에서 단답형 변경 전후 점수를 표시한다. 바뀐 답안·재응시에 과거 정정 표시를 붙이지 않는다.

## 이번 적용 상태

운영 은행 내보내기가 최종 승인본과 일치하며 배정 비밀값과 다른 환경 변수는 변경하지 않았다. DB 정정 이후 변경 대상 점수, 원본 답안·Part 3·비대상 자료·보관 원본 보존 및 감사 스냅샷을 재조회했다. 학생별 완료 내역은 비공개 `scratch/v4-review/student-corrections.md`, 실행·재조회 근거는 같은 폴더의 적용 결과·검증 파일에 있다. 초기 검토본과 이전 계획은 운영 기준이 아니며 다시 실행하지 않는다.

교사·학생의 열려 있던 화면은 새로고침하고 성적표는 새로 내보낸다. 정정 학생만 모아보는 운영 화면은 추가하지 않았으며, 위 비공개 완료 목록으로 확인한다. 기존 보관 회차 변경 대상은 없어 보관 원본을 수정하지 않았다.

## 재실행을 위한 절차와 복구

아래는 후속 정정·장애 복구를 위한 절차이며 이번 적용이 미완료라는 의미가 아니다. 새 인정 기준과 대상은 별도 검토하고 최신 소스와 비교한다.

1. 이 PC의 Git·배포 제외 `scratch/v4-review/`에 운영 은행 원본, 승인 은행, 수정 목록, 원본 학생 스냅샷, 해시가 포함된 정정 계획을 보관한다. 이 폴더와 서비스 로그인은 다른 PC로 자동 전달되지 않는다. 공개 Git에 추가하지 않는다.
2. 적용 직전 운영 은행이 백업과 동일한지, 진행 중 V4가 없는지, 계획의 소스 문서가 그대로인지 다시 확인한다. 변경되었으면 새 비교를 만든다.
3. 운영 병합·배포 승인 후 서버 파서 확장과 승인 은행을 함께 반영한다. 새 은행을 12개 제한의 이전 서버에 먼저 적용하면 오류가 나므로 함께 전환한다. Vercel의 은행 환경 변수 외 다른 비밀값은 변경하지 않는다.
4. 새 배포의 교사 은행 내보내기와 실제 서버 채점 결과를 확인한 다음 다음 명령으로 검토된 DB 정정을 실행한다. 도구는 관리자 Firebase CLI 인증을 사용하며 학생이나 일반 브라우저가 실행하지 않는다.

```powershell
node tools/apply-objective-regrade.cjs --plan scratch/v4-review/regrade-plan.json --confirm-plan <검토한-planHash>
node tools/apply-objective-regrade.cjs --plan scratch/v4-review/regrade-plan.json --confirm-plan <검토한-planHash> --apply
```

5. 저장 후 원본 답안·Part 3·학생 수·정정 점수를 재조회한다. 학급별 트랜잭션이므로 중간 장애가 나면 완료 그룹을 확인하고 같은 해시로 재실행한다. 운영 교사/학생/내보내기는 현행 은행에서 계산하므로 열려 있던 화면을 새로고침하고 성적표를 다시 내려받는다.
6. 복구가 필요하면 기존 은행/배포를 복원한 뒤 아래 명령으로 원래 점수 필드와 정정 필드의 부재까지 복원한다. 이후 점수를 다른 사람이 수정했다면 자동 복구를 거부한다. 적용·복구 감사 문서는 모두 남긴다. 복구한 계획의 재적용은 거부한다.

```powershell
node tools/apply-objective-regrade.cjs --plan scratch/v4-review/regrade-plan.json --confirm-plan <검토한-planHash> --apply --restore
```

## 검증 근거와 남은 범위

- 2026-09-24 로컬: 전체 단위 테스트 137개 통과. 상한 경계, 변조 계획·변경된 답안 거부, 원자적 감사 저장, 재실행, 원복, Part 3 보존을 포함한다. API 학생 본인·담당 교사·다른 학생·담당 밖 교사 거부는 모의 테스트다.
- 비공개 승인 은행의 허용답과 오답/부정 표현이 채점과 교사 상세 판정에서 일치한다. 교사가 제외한 표현의 공백 변형도 오답으로 확인했다. 합성 배정 1,000회에서 기존 문항 배정과 동일하다.
- 로컬 Edge 데모: 보관 정정 표시, 원본 저장소 불변, 검색·키보드 이동, 1440/1024/768/390px 확인. 콘솔 오류·페이지 예외 0건. 외부 Firebase/CDN을 차단한 검사로 실제 로그인·운영 CSS 전체 확인을 대신하지 않는다.
- 운영 읽기 전용: 기존 교사의 담당 학급 허용, 담당 외 학급 거부, 비로그인 거부를 API와 Firestore 각각 확인(6건). 실제 학생 계정의 운영 요청은 이번에 새로 검증하지 않았다.
- 운영 배포·은행 교체·DB 정정·DB 재조회 완료. 담당 범위 내 서버 단답형 점수도 저장 답안으로 계산한 기대값과 일치했다. 정정 대상 학급은 운영 검사 계정의 담당 범위 밖이므로 그 학급의 서버 결과를 우회 조회하지 않았다. 정확한 배포 은행과 정정 DB는 확인했지만 대상 학급의 실제 교사/학생 화면 전체·재내보낸 엑셀·NEIS 일치까지 검증한 것은 아니다.
- 운영 정적 파일이 검증본과 일치한다. 실제 CDN을 사용하는 운영 페이지에 합성 자료만 넣어 정정 표시와 1440/390px 줄바꿈을 확인했고 페이지 예외·콘솔 오류는 없었다. 학생 로그인·운영 답안 쓰기·AI 호출 없이 확인했다.
