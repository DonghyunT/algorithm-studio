# 수행평가 문항 버전 4 준비 계획

상태: **계획**  
갱신: 2026-09-15  
대상: 수행평가 Part 1·2의 문항 품질과 정답·채점 무결성

## 1. 이번 전환의 의도

V3의 문항을 "버리기" 위한 작업이 아니다. 이미 만든 개념 문제와 난이도 균형을 교육 자산으로 보존하고, 학생이 단순히 용어를 기억했는지가 아니라 조건을 읽고 알고리즘의 작동을 판단하는지를 더 잘 확인하기 위한 전환이다.

동시에 평가용 정답과 자동 채점 근거가 학생 브라우저에 전달되는 현재 구조를 끝낸다. 학생이 GitHub 주소를 알지 않더라도 시험 페이지가 정답을 내려보내면 개발자 도구로 확인할 수 있으므로, 공개 저장소의 존재 여부와 별개로 보호 경계를 바꿔야 한다.

V3은 과거 회차 답안의 재현과 일반 연습을 위해 유지한다. V4는 새 평가 회차에서만 선택하며, V3 답안을 V4 기준으로 재채점하지 않는다.

## 2. V4 문항 품질 기준

### 학습 목표를 유지하는 방식

| 영역 | 유지할 핵심 | V4에서 높일 점검 수준 |
|---|---|---|
| 알고리즘의 조건 | 입력·출력·명확성·유한성·수행 가능성 | 정의를 고르는 문제뿐 아니라 실제 지시가 조건을 만족하는지 판별 |
| 순서도 기호 | 단말·자료·판단·처리 역할 | 기호 이름 암기보다 상황에 맞는 역할 선택 |
| 제어 구조 | 순차·선택·반복 | 조건의 참·거짓, 실행 순서와 반복 종료를 근거로 결과 추론 |
| 경계값과 추적 | 비교 연산과 반복 실행 | `이상/초과/미만`의 경계, 누적·남은 값·종료 시점을 한 단계씩 확인 |
| 실생활 적용 | 학생이 읽을 수 있는 생활 맥락 | 특정 가정·용어를 알아야만 풀리는 배경지식은 배제 |

### 한 문항마다 지킬 기준

1. 학생이 무엇을 판단해야 하는지 한 문장으로 설명할 수 있어야 한다.
2. 정답은 지문과 수업에서 배운 개념만으로 하나로 결정되어야 한다.
3. 오답 보기는 같은 범주와 문법 형태를 유지하되, 흔한 오개념을 반영한다. 터무니없는 보기나 글자 수 힌트는 사용하지 않는다.
4. 한 문제에 새 개념을 여러 개 겹쳐 묻지 않는다. 긴 독해력·계산 속도·가정 환경의 차이가 점수를 좌우하지 않게 한다.
5. 단답형은 허용 가능한 표기 차이를 명시적으로 검토한다. 자동 채점이 애매하면 교사 확인 대상으로 남기거나 문항을 고친다.
6. 실제 수업에서 풀이 과정 자체가 공개된 예시를 그대로 평가 문항으로 재사용하지 않는다. 같은 개념은 상황·수치·판단 경로를 새로 구성한다.

## 3. 배정과 난이도 원칙

현재 30분·총 100점 구조(Part 1 10문항 30점, Part 2 6문항 30점, Part 3 40점)는 유지한다. V4의 모든 배정 조합은 다음을 확인한다.

* Part 1에는 쉬운 개념·적용, 중간 난이도 판단, 높은 난이도 추론이 균형 있게 포함된다.
* Part 2에는 기본 기호·제어 구조 확인, 경계값 판단, 실행 추적 또는 복합 상황 판단이 균형 있게 포함된다.
* 같은 학생의 Part 1·2에 같은 정답어 또는 거의 같은 사고 과정을 중복 배정하지 않는다.
* 학생별 문항은 서로 달라도 총 난이도와 배점이 동등해야 한다. 이 값은 추측이 아니라 배정 도구의 자동 검사로 확인한다.

## 4. 공개 범위와 보안 경계

| 자료 | 학생 브라우저 | 공개 Git 저장소 | 서버 보호 영역 |
|---|---|---|---|
| 수업용 개념·연습 자료 | 가능 | 가능 | 필요 없음 |
| V3 과거 문항·답안 구조 | 기존 기록 범위 | 기존 공개 상태 | 변경하지 않음 |
| V4 학생에게 배정된 문제 본문 | 해당 학생에게만, 평가 중 | 시험 전 공개 여부 별도 결정 | 배정 API가 전달 |
| V4 정답·유사 정답·배정 비밀값 | 불가 | 불가 | 서버만 읽고 채점 |
| 확정 점수 | 본인 결과·담당 교사 범위 | 불가 | 권한 규칙으로 보호 |

V4에서는 학생 브라우저가 점수를 계산하거나 정답 목록을 보유하지 않는다. 제출 후 서버가 회차·학생 소유·문항 배정·답안 형식을 확인하고 점수를 계산한다. Firestore에는 학생이 바꿀 수 없는 배정 식별자와 서버가 계산한 결과를 구분해 저장한다.

## 5. 구현 전 확인할 선택

V4 문항 본문을 시험 전에도 공개 저장소에서 볼 수 있게 둘지, 정답뿐 아니라 문항 본문도 시험 전 비공개로 둘지 결정해야 한다. 후자를 택하면 GitHub 저장소 공개 범위 또는 별도 보호된 문항 저장소를 함께 조정해야 한다. 이 선택은 문항의 교육적 품질과는 별개로 시험 운영 방식에 영향을 준다.

## 6. V4 완료 조건

1. 새 회차에서 학생 전달 코드와 공개 저장소에 정답·유사 정답·채점 함수가 없다.
2. 학생은 자신에게 배정된 문항만 받고, 직접 요청을 바꾸어 다른 문항·다른 학생 기록·정답을 얻을 수 없다.
3. 서버 채점 결과가 학생이 보낸 임의 점수보다 우선하며, 제출 후 답안 변경은 기존 마감 규칙과 함께 거부된다.
4. 문항별 교육 목표·정답 근거·오개념 보기·유사 정답·난이도 점검 기록이 교사 전용 검토 자료에 남는다.
5. 기존 V3 회차 조회와 새 V4 회차의 학생·교사 대표 흐름이 각각 깨지지 않는다.

## 7. 다음 순서

1. 시험 전 문항 본문 공개 범위를 결정한다.
2. V3 문항의 학습 목표·중복·애매성·난이도 진단표를 만든다.
3. 진단표를 바탕으로 V4 문항 청사진과 교사 전용 정답 검토 자료를 준비한다.
4. 서버 전용 배정·채점 경계와 Firestore 규칙을 구현하고 공격 시나리오 검사를 추가한다.
5. 교사 검토 후에만 V4 새 회차를 운영 배포한다.
