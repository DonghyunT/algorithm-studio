# 개발과 검토 절차

## 이번 작업

* 기준 커밋: `cacfc5e`
* 개발 브랜치: `codex/classroom-reliability`
* 합의된 범위: PRD의 실습·수행평가 도움 및 제출 정책, 저장·복구·권한·실행 신뢰성 보완, 감사 발견 사항의 회귀검증.
* 승인된 인증: 교사 Google 계정과 등록된 교사 역할, 학생 학급/번호/이름 및 내부 익명 인증.
* 별도 협의: 평가 마감·재시험 세부 규칙, 다음 차시 이어하기 및 보관 기간.

## 간단한 개발 흐름

1. 요구사항과 재현 사례를 문서로 확인한다.
2. 개발 브랜치에서 목적별로 수정하고 작은 커밋으로 기록한다.
3. 기존 오류를 재현하는 검사와 정상 사용 흐름을 함께 검증한다.
4. 변경 내용·검증 결과·남은 제한을 정리하고 검토 요청(PR)을 준비한다.
5. 선생님이 결과를 확인하고 명시적으로 승인한 뒤에만 main에 병합한다.

main에 push하면 운영 Vercel 배포가 실행될 수 있으므로 승인 전 main 병합·push를 하지 않는다. 미리보기 배포도 운영 Firebase와 자동 분리되는 것은 아니다. 테스트에서 운영 DB를 쓰지 않도록 구성한 뒤 미리보기를 사용한다. Firestore 규칙 배포는 Git 브랜치와 별개로 운영에 영향을 주므로 별도 검증 후 적용한다.

## 완료 보고에 포함할 내용

* 무엇이 달라졌는지와 학생·교사에게 미치는 영향
* 실행한 검사, 통과·실패, 환경과 버전
* 해결한 감사 항목과 남은 항목
* 인증 설정·운영 배포 등 후속 작업

자동 검증 통과만으로 모든 교실 환경의 정상 동작을 보장하지 않는다. 미검증 항목은 명확히 남긴다.

검토 버전의 실행법과 결과는 [구현 검토서](IMPLEMENTATION_REVIEW.md), 운영 전환 조건은 [운영 준비](OPERATIONS.md)를 참고한다. 현재 원격 push/PR 생성은 하지 않았으며, 먼저 로컬 diff와 시연을 검토한다. 원격 Preview와 운영 DB 분리 후 PR을 연다.
