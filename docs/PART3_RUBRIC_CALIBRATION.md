# Part 3 채점 기준과 검증 기록

2026-09-24. 요구사항은 [PRD](../PRD.md#32-수행평가), 배포 상태는 [배포 기록](DEPLOYMENT.md)을 따른다. 실제 학생 자료·성적·학생 수는 공개 문서에 포함하지 않는다.

## 기준

| 항목 | 만점 | 허용 점수 |
|---|---:|---|
| 현재 상태 | 5 | 5 / 4 / 3 / 0 |
| 목표 상태 | 5 | 5 / 4 / 3 / 0 |
| 조건 | 5 | 5 / 4 / 3 / 0 |
| 자연어 기획서 | 5 | 5 / 4 / 3, 미작성 2 |
| 순서도 문제 해결 논리 | 10 | 10 / 8 / 6 / 4 / 2 / 0 |
| 순서도 구조·표현 | 10 | 10 / 8 / 6 / 4 / 2 / 0 |

맥락에 맞고 논리적 오류가 없으면 만점이다. 상태·조건의 작은 오류는 4, 큰 오류는 3, 미작성은 0이다. 길이·조건 개수·주제의 단순함으로 감점하지 않는다. 자연어 안내 부족을 고려하여 미작성은 2점이며 순서도와 분리한다. 의미 있는 순서도에는 가능한 한 6점 이상, 극히 미완성일 때 4/2점을 사용하며 같은 원인을 중복 감점하지 않는다.

외딴 블록은 감점하지 않는다. 연결된 본체가 있으면 연결선에 전혀 참여하지 않는 블록은 AI 입력에서 제외한다. 모든 블록이 미연결이면 내용은 논리 증거로 인정하고 구조만 미완성으로 평가한다. 연결된 비단말 기호의 후속선 누락은 구조 8점 이하, 의미 있는 기호 전체 미연결은 구조 4점 이하로 검증한다. 핵심 분기 반전은 논리에서 감점하고 연결 자체가 완결됐으면 구조에서 중복 감점하지 않는다.

Part 3는 `max(6, 항목 합계)`이며 기본 6점을 가산하지 않는다. 완전 미작성은 AI 없이 항목 합계 2 + 최저점 보정 4 = 6점이다. AI 실패는 6점으로 대체하지 않고 대기로 남긴다.

총점은 지필 60 + Part 3 40이다. 최종 환산만 `2 × ceil(총점 × 0.3 / 2)`로 계산하여 다운로드 성적표에 표시한다. 70→22, 75→24, 100→30이며 원점수의 홀수는 유지한다. 유효한 AI 결과는 배부용 잠정점수, 교사 수정은 교사 정정으로 구분한다.

## 버전·저장·복구

- 새 실전평가는 `open-design-v2`를 사용하며 기존 V1 네 항목 및 모의평가 기준은 보존한다.
- 도입 시 각 반의 최근 두 번 실제 시작·종료된 V4만 선정한다. 현재/보관 회차를 합쳐 attemptId로 중복 제거하며 대기·진행·모의·학생 초기화 감사 사본은 제외한다.
- 사용자는 대상 내 기존 교사 확정/수동 총점까지 교체하고 하락도 반영하도록 승인했다. 변경 전 답안·점수·검토를 로컬 해시 백업 및 서버 추가 감사 사본으로 보존한다. 학생 답안과 지필 항목은 바꾸지 않는다.
- 답안·회차·기준 버전이 일치하는 결과는 재사용한다. 도입 후 교사 정정이 우선한다. 현재 회차는 검토 이력, 보관 회차는 추가 정정 기록을 남긴다.
- `tools/apply-part3-regrade.cjs`는 계획 해시·갱신시각을 검사하고 회차별 트랜잭션으로 백업과 교체를 함께 수행한다. 동일 계획은 중복 쓰기 없이 종료한다. 보관 원본은 그대로 두고 추가 감사 결과를 표시한다.
- 같은 도구의 `--restore`는 현재 회차의 세 필드를 당시 존재 여부까지 복원하고, 보관 회차의 추가 결과를 비활성화하는 복구 감사 기록을 만든다. 이후 답안/교사 정정이 바뀌면 자동 복원하지 않는다. 코드 복구는 별도 Git revert/배포 복원이다.
- 비공개 복구·호출 장부는 Git 제외 `scratch/part3-v2/`에 있다. 적용 명령에는 그 안의 plan.json과 `--confirm-plan` 해시가 필요하다. 학생 자료를 PR·로그에 복사하지 않는다.

## 검증

- 9,216개 점수 조합의 범위·최저점·비감소성, 환산 경계·소수값, 누락/중복·불허 점수, 다른 답안/회차/기준의 캐시 거부를 자동 검사했다.
- 실제 Solar 모델 합성 시험은 총 40회(승인 상한 40)다. 초기 시험에서 분기 반전과 끊긴 연결의 오판을 발견해 방향별 연결 정보와 감점 귀속 지침을 추가했다. 외딴 블록은 입력에서 제외했다. 실제 결과 검토 후 정상 반복, 이미 완료한 경우의 분기, 맞춤법/짧은 표현, 기본 문구만 있는 시도의 판단을 보강했다. 마지막 합성 네 사례(`tests/fixtures/part3-sanity.cjs`)는 모두 기대값과 일치했다. 앞선 실패도 비공개 기록에 보존하며 모든 학생 채점의 정확성을 입증한 것으로 해석하지 않는다.
- 모의 API로 권한 경계·미제출 거부·빈 답안 무료 처리·개인정보 필드 제외·교사 정정 재사용을 확인했다. 적용/복원 모의 검사는 원본·지필 보존, 확정점수 교체, 멱등성, 답안 변경 중단, 이후 정정의 복원 거부, 보관 원본 불변을 확인했다.
- 기존 전체 Edge 회귀 24개와 새 여섯 항목의 불허 점수 거부/정정 저장/320~1440px 조작을 확인했다. 페이지·콘솔 오류는 0이었다.
- 합성 XLSX를 독립 OpenXML 리더로 열어 여섯 항목·병합 영역·환산·정정 상태를 확인했다. 실제 NEIS 업로드나 실제 Excel 인쇄 검증은 아니다.

## 성적표

다중 시트 XLSX를 유지하고 학급종합·나이스에 환산/30과 상태 열을 추가했다. 학생별 상세에는 항목별 5/10점 만점, 근거, 항목 합계와 최저점 보정을 표시한다. 보관 회차에도 해당 회차 다운로드와 새 기준 교사 정정을 제공한다. V4 보관 문항 원문이 없으면 현재 은행으로 과거 정답을 재구성하지 않는다. 지필 점수까지 없으면 총점·환산을 만들어 내지 않는다.

## 실제 적용 완료와 한계

2026-09-24 사용자가 Upstage Solar API와 사용자 소유 비공개 Vercel Preview 경로를 명시 승인했다. 대상 원본과 백업 일치를 재확인한 뒤 채점했고, 앱 재시작 시 이미 저장한 결과는 재사용했다. 빈 답안은 AI 없이 계산했다. 감점 항목의 근거·연결과 기본 문구만 남은 답안을 대조하여 금지된 감점과 놓친 오류를 바로잡았다. 이는 교사가 직접 확정했다는 뜻이 아니며 모두 잠정점수로 저장했다.

검증된 계획을 `tools/apply-part3-regrade.cjs`로 적용하여 회차별 서버 원본 감사 사본과 점수 교체를 원자적으로 완료했다. 서버 전체 대상 재조회에서 원본 답안·지필 및 채점 외 필드 불변, 감사 원본 일치, 저장 점수와 계획 일치를 확인했다. 보관 답안은 원본을 그대로 두고 추가 결과로 제공한다. 이후 동일 계획을 다시 채점할 필요가 없다.

기존 담당 교사 계정으로 운영 화면의 여섯 항목·잠정 표기와 실제 XLSX 다운로드를 확인했고, 이 화면 검증에서는 학생 쓰기와 AI 호출이 없었다. 독립 OpenXML 리더로 지필+서술 총점 및 짝수 환산을 대조했다. 보관 원본에 지필 점수·당시 배정 문항이 없는 경우 서술은 표시하되 총점·환산은 대기로 유지한다. 현재 문제은행을 과거 원문으로 임의 대체하지 않는다. 실제 학생 본인 로그인·NEIS 업로드·실제 Excel 인쇄는 이번 추가 검증 범위가 아니다.

비공개 완료 근거는 `scratch/part3-v2/`의 `graded.raw.json`(원래 AI 응답), `reconciliation.json`(근거 대조 조정), `plan.json`(해시 적용 계획), `applied.json`, `verified.json`, `live-ui.json`, `live-report.xlsx`다. 공개 Git으로 전달하지 않는다. 복구 시 동일 계획 파일과 해시를 사용하고 이후 교사 정정이 있으면 자동 복원하지 않는다.
