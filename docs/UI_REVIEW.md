# 상단 탐색과 공통 UI 개편 검토

2026-09-12 · 기준 버전 `0a7545c`에서 `codex/responsive-studio-ui`로 작업. 사용자가 문서 지침의 구현과 Vercel 배포를 요청했습니다.

## 문제와 변경

기존 상단은 로고·학습 메뉴·관리 버튼이 모두 줄어들지 않는 한 줄 배치였고, 읽기 화면에서는 헤더 폭도 1,200px로 제한되어 창이 좁아지면 메뉴가 밀렸습니다. 학생 학습 메뉴 안에 교사 버튼이 섞여 있었고 홈에도 같은 진입점이 반복됐습니다.

상단 관리 영역에 이름이 보이는 교사용 버튼과 전체 메뉴를 배치했습니다. 좁은 창에서 학습 메뉴가 다음 줄로 이동하며, 실습 높이는 실제 헤더 높이를 따라 계산합니다. 전체 메뉴의 실습 바로가기는 유지하고 호버 자동 열기를 제거했습니다. 버튼·키보드로 열고 닫을 수 있으며 평가 중 이동 잠금도 적용합니다.

홈은 큰 배너와 중복 설명 대신 세 학습의 개념·퀴즈·실습을 직접 선택하도록 구성했습니다. 연결 대상이 없던 심화 탐구 버튼은 제거했습니다. 글자·간격·강조색·경계선의 공통 기준을 추가하고, 개념 배너와 교사·평가 도구 모음을 정리했습니다. 기존 교육용 그림과 순서도 기호 색상, 학생이 직접 작성하는 평가 처방전은 유지합니다.

실화면 검토에서 추가로 발견한 순서도 단계 메뉴의 높이 고정에 따른 겹침과 시작 기호를 덮는 안내 문구도 수정했습니다. 새 프레임워크나 제품 빌드 도구는 도입하지 않았습니다. 서버 API, 채점 기준, Firebase 규칙과 운영 데이터는 이번 변경 대상이 아닙니다.

## 참고한 디자인 원리

* [네이버 메인](https://www.naver.com/)의 실제 화면을 2026-09-12 확인했습니다. 주요 기능과 관리 기능의 분리, 일정한 본문 폭, 텍스트와 경계선 중심의 정보 구분을 참고했습니다. 포털의 정보량이나 고정 폭을 그대로 따르지 않고 교실의 창 크기 변화에 맞추었습니다.
* [Google Material Design 3 Foundations](https://m3.material.io/foundations/)의 접근성·레이아웃·상태 표현·공통 스타일 값 관리 원칙을 참고했습니다. 라이브러리를 설치하거나 외형을 복제하지 않았습니다.

## 검증 방법과 범위

최종 로컬 결과: 문법·파일 참조 검사 통과, 기본 기능 12개 통과, 브라우저 시나리오 23개 통과. 브라우저 검사에서 페이지 예외와 콘솔 오류는 0개였습니다. 아래 검사는 이 개편의 로컬 코드와 모의 서비스 환경을 대상으로 합니다.

* `node tools/check.cjs`: 34개 스크립트 문법과 HTML의 로컬 파일 참조.
* `node --test --test-isolation=none tests/core.test.cjs tests/api.test.cjs tests/rounds.test.cjs`: 채점·표현식·API 인증·회차 보관 등 12개 검사.
* `node tests/browser.cjs`: 실제 Edge 렌더링에서 창 폭별 버튼 경계와 클릭 가능 여부, 전체 메뉴 키보드 초점, 홈 바로가기, 개념·퀴즈·교사·평가 화면, 평가 저장 실패·재접속·이동 잠금 검사. Firebase와 AI는 모의 환경을 사용하므로 실제 교사 인증·운영 DB 저장을 재검증한 것은 아닙니다.
* 상단 검사 폭: 320, 360, 390, 430, 431, 540, 680, 681, 768, 900, 1100, 1250, 1251, 1350, 1351, 1440, 1920px. 개념·퀴즈·교사·대기실 본문은 390/768/1024/1440px. 실습은 768/1024/1366/1440/1920px. 추가 결과 버튼 표시와 본문 글자 확대도 검사합니다.
* 결과는 [browser.json](../tests/results/browser.json), 대표 화면은 [홈](../tests/results/view-roadmap.png), [좁은 홈](../tests/results/home-320.png), [개념](../tests/results/view-concept.png), [교사](../tests/results/ui-classroom-390.png), [순서도 실습](../tests/results/studio-1024.png), [평가](../tests/results/assessment.png)에 보관합니다.

기존 자동 검사 통과를 전체 UI 또는 교실 운영의 무결성으로 확대하지 않습니다. 모바일 터치로 복잡한 순서도를 만드는 흐름, 실제 학급 동시 사용과 모든 운영체제·브라우저의 글꼴 차이는 별도 확인 대상입니다. 배포 결과는 배포 후 [운영 기록](DEPLOYMENT.md)에 추가합니다.
