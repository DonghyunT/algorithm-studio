# 운영 반영 전 준비

이 문서는 `codex/classroom-reliability` 검토 버전의 배포 절차입니다. 새 코드와 보안 규칙을 아직 운영에 적용하지 않았습니다. 기존 Firebase 자료는 사용자 확인상 테스트 자료입니다.

## 먼저 분리된 검토 환경

로컬에서는 `node tools/preview.cjs`로 시연합니다. Vercel Preview는 기본적으로 운영 Firebase 설정을 그대로 읽으므로 브랜치 push만으로 안전한 테스트 환경이 되지 않습니다. 원격 PR/Preview를 만들기 전 테스트 전용 Firebase 프로젝트 설정 또는 Preview에서 원격 저장을 차단하는 구성이 필요합니다. 로컬 시연은 로그인·서버 권한 시험을 대신하지 않습니다.

## Firebase 인증과 데이터

1. 테스트 프로젝트의 Authentication → Sign-in method에서 Google과 Anonymous 제공자를 활성화합니다. Google 공급자의 지원 이메일을 설정합니다.
2. Authentication의 승인 도메인에 사용할 테스트 도메인을 등록합니다. 운영 적용 시 실제 Vercel 도메인도 확인합니다.
3. 교사 Google 계정으로 로그인한 뒤 Authentication의 Users에서 해당 UID를 확인합니다. 관리자가 Firestore `teachers/{해당 UID}` 문서를 만들고 `enabled: true`를 지정합니다. 이메일 이름이나 학생 입력값으로 권한을 주지 않습니다.
4. 기존 테스트 `eval_sessions`/`students` 기록은 `ownerUid`, 세션 `deadlineMs`가 없는 이전 형식입니다. 그대로 운영 데이터로 사용하지 않습니다. 백업 여부와 시험용 초기화를 확인한 뒤 새 테스트 좌석으로 검증합니다. 이 브랜치가 기존 자료를 자동 삭제하거나 마이그레이션하지는 않습니다.
5. 테스트 환경에 새 규칙을 적용하고 교사, 학생 A, 학생 B, 미로그인 사용자의 네 역할로 시험합니다. 학생 B가 A의 문서를 읽거나 변경하지 못하고, 학생이 세션·점수·교사 역할을 변경하지 못해야 합니다.
6. 마감 전 자동 저장, 마감 후 수정 거부, 같은 답안 제출 확정, 제출 직후 네트워크 단절 및 재시도, 교사 초기화, 다른 PC에서의 복귀를 확인합니다.

현재 교사 초기화는 기존 응시 문서의 답안을 지우며, 사용 중인 인증 UID는 유지합니다. 기존 30분이 끝났다면 단순 초기화가 새 시간을 부여하지 않습니다. 새 회차 보관과 번호 재배정은 별도 정책/구현이 필요합니다. 다음 학생이 같은 창을 쓰기 전 '로그아웃 · 사용 종료'를 사용하거나 창을 닫습니다. 미제출 상태의 사용 종료는 차단합니다.

## AI와 Vercel

서버 환경변수 `UPSTAGE_API_KEY`를 설정합니다. `FIREBASE_PROJECT_ID`는 Firebase Web 설정의 프로젝트와 일치해야 합니다. `SOLAR_MODEL`은 필요 시 서버에서 지정합니다. API 키를 소스, 브라우저 설정, 문서에 넣지 않습니다. 기존 로컬 `config.js`는 더 이상 로드하지 않으며 배포 제외 목록에 있습니다.

API는 Firebase ID 토큰 서명/발급자/프로젝트/만료를 검증하고 고정된 응답 길이를 사용합니다. 현재 UID별 분당 10회 제한은 **함수 인스턴스 안에서만** 적용됩니다. 새 익명 계정 생성과 여러 인스턴스를 합친 총량 제한이 아닙니다. 공개 운영 전 비용 한도/분산 요청 제한 또는 교사 발급 학급 접근 정책을 보완해야 합니다. 평가 중 AI 차단은 현재 앱 상태에 따른 클라이언트 제한으로, 다른 창·직접 API 요청을 통제하지 않습니다.

실제 모델 응답, 로그인 토큰 갱신, 시간 초과, 사용량/비용 제한을 테스트 키와 테스트 프로젝트에서 확인합니다. `.vercelignore`가 문서·테스트·비밀 파일을 제외하는지 배포 산출물도 확인합니다.

## 승인 후 운영 반영

테스트 결과와 남은 제한을 교사가 검토한 뒤 main 병합을 명시적으로 승인합니다. Firestore 규칙은 Git 병합과 별개로 적용됩니다. 이전 앱과 새 규칙의 호환성이 없으므로 수업 중 전환하지 않고, 앱/규칙/인증 설정을 함께 반영할 시간을 정합니다. 이전의 공개 규칙으로 되돌리는 방식의 롤백은 사용하지 않습니다.

운영에서 교사 로그인, 시험용 학생 제출, 교사 조회, CSV를 확인한 뒤 학급 사용을 시작합니다. 실제 27명 동시 접속과 NEIS CSV 가져오기는 별도 확인 항목입니다. 서버 보관·삭제 기간도 수업 운영 전에 정해야 합니다.
