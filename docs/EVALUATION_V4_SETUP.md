# V4 수행평가 문항 설정과 백업

갱신: 2026-09-19 · 기준 코드 `a998d3c`. V4 운영 설정·80문항 은행·교사 백업은 반영되어 있습니다. 이 문서는 현재 설정과 향후 변경 절차를 설명하며, 새 운영 검증 기록은 아닙니다. [PRD](../PRD.md), [배포 기록](DEPLOYMENT.md)을 기준으로 읽습니다.

## 현재 설정

| 항목 | 현재 방식 |
|---|---|
| 평가 유형 | 교사 준비 화면에서 V4 실전평가 또는 V3 모의평가 선택, 기본값 V4 |
| 문항 은행 | `EVAL_BANK_V4_JSON` · 객관식 50 + 단답형 30문항, 운영 등록 기록 있음 |
| 배정 비밀값 | `EVAL_ASSIGNMENT_SECRET` · 32자 이상, 회차·학급·번호별 배정에 사용 |
| 학생 응답 | 본인 배정 문항의 본문·보기. 정답·허용 답·출제 의도 제외 |
| 교사 조회 | 제출 답안의 채점·문항 검토, 활성 교사 역할의 전체 은행 백업 |

서버 파서는 일반 JSON과 gzip-base64를 지원합니다. 압축 해제 후 JSON 문자열 길이는 20~200,000이며 형식 검사를 거칩니다. 2026-09-18 배포 기록은 원본 73.8KB를 gzip-base64 24.7KB로 등록했다고 명시합니다. 이는 당시 기록이며 현재 환경 변수 값을 이번에 내려받거나 측정한 것은 아닙니다. 플랫폼 용량과 다른 환경 변수 사용량은 다음 변경 시 별도로 확인합니다. 파서 길이 상한을 배포 용량 보장으로 해석하지 않습니다.

문항 공통 필드는 `id`, `title`, `desc`, `teacherNote`, `difficulty`, `subType`, `points`입니다. 객관식은 `options`, `correctAnswer`, 단답형은 `answers`와 입력 안내 `placeholder`를 사용합니다(파서는 안내 누락 시 기본 문구 허용). 영역별 배정 구성은 [PRD 3.6절](../PRD.md)을 따릅니다. 실제 문항·정답·비밀값은 공개 문서에 기록하지 않습니다.

## 다른 PC에서 백업 받기

1. 운영 웹에서 교사로 로그인하고 학급 선택 바의 `[⬇ 백업]`을 선택합니다.
2. 내려받은 JSON은 필요한 경우 해당 PC의 `scratch/eval_bank_v4.json`에 보관합니다. Git 제외 여부와 접근 가능한 위치를 확인합니다.
3. 로컬 검토 도구의 입력 설정을 확인해 사용합니다. 다운로드만으로 운영 인증·DB·테스트 환경이 구성되지는 않습니다.

`export-bank`는 비익명 사용자 중 `enabled: true`이고 전체 반 또는 하나 이상의 담당 반 역할이 있는 교사에게 전체 은행을 반환하는 현재 구현입니다. 학생 답안 조회의 담당 반 제한과 구분합니다. 환경 변수 전체를 내려받을 필요 없이 이 경로로 문항 JSON을 받을 수 있습니다.

압축 환경 변수 내용을 그대로 JSON으로 저장하지 않습니다. 이 백업에는 배정 비밀값, 이전 은행 버전, 학생 답안, 당시 채점 코드가 포함되지 않으므로 완전한 회차 복구본으로 취급하지 않습니다.

## 은행·배정 설정을 바꾸기 전

현재 은행과 배정 비밀값을 덮어쓰면 기존 회차의 문항·보기 순서·채점 재현에 영향을 줄 수 있습니다. 새 회차 준비만으로 이전 기준이 보존되는 것은 아닙니다. 회차별 버전 고정, 보관 기간, 키 교체, 복구 및 성적 정정 절차는 [V4 계획 9~10절](EVALUATION_V4_PLAN.md#9-보안보관유지보수-상세-검토)의 후속 설계 대상입니다.

변경은 다음 순서로 준비합니다.

1. 기존 회차를 재현할 은행·배정·채점 기준과 복구 방법을 정하고 변경 범위를 협의합니다.
2. 비공개 장소에서 수정본과 정답·허용 답·배정 균형을 검토합니다. 공개 Git에 실제 자료를 추가하지 않습니다.
3. 분리된 검증 환경에서 학생 입장·저장·제출·교사 조회, API 권한과 Firestore 직접 접근을 각각 확인합니다.
4. 이전 회차 재현·확정 성적 보존과 실패 복구 결과를 기록합니다. 교실 동시 사용은 별도 검증으로 구분합니다.
5. 해당 운영 변경 승인 후 반영합니다. Preview도 운영 Firebase와 자동 분리되지 않습니다.

기존 설정을 새 PC에서 다시 등록하거나 운영 은행·비밀값을 임의로 교체하지 않습니다.
