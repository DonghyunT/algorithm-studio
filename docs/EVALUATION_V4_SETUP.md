# V4 수행평가 서버 문항 설정 안내

상태: **P0 운영 배포 완료 · V4 운영 설정 전**
갱신: 2026-09-15

이 문서는 P0의 현재 설정 방식과 V4 운영 전 준비 조건을 설명합니다. 실제 설정을 시작하기 전에 [V4 계획 8~11절](EVALUATION_V4_PLAN.md#8-다음-순서와-활성화-조건)의 회차 재현·비공개 보관 설계를 확인합니다. 학생에게는 본인의 배정 문항만 전달하며, 전체 문항 은행·정답·유사 정답·출제 의도는 공개 Git, 학생 응답, 공개 공유 문서에 넣지 않습니다.

## 보호되는 자료와 교사 확인 범위

`EVAL_BANK_V4_JSON`에는 Part 1·2의 문항, 정답, 허용 답, 난이도, 출제 의도를 둡니다. 서버는 학생에게 문항 본문·보기만 전달하고, 정답·허용 답·`teacherNote`는 전달하지 않습니다. 제출 뒤 담당 교사가 학생 답안 상세 창을 열면 서버가 문항·정답·출제 의도를 교사에게만 보여 줍니다.

각 문항은 다음 정보를 모두 가져야 합니다.

| 공통 | Part 1 객관식 | Part 2 단답형 |
|---|---|---|
| `id`, `title`, `desc`, `teacherNote`, `difficulty`, `subType`, `points` | `options`, `correctAnswer` | `placeholder`, `answers` |

`teacherNote`에는 “이 문항으로 확인할 사고 과정, 정답 근거, 주요 오개념”을 짧고 분명하게 기록합니다. 학생 화면에는 전달되지 않습니다.

## 운영 환경 변수

아래는 현재 P0가 사용하는 설정입니다. 보관·버전 설계와 해당 운영 작업의 승인 후 Vercel Production 또는 분리 여부를 확인한 검증 환경에 등록합니다. Preview라고 운영 DB와 자동으로 분리되지 않습니다. 두 값은 **서로 다른 비밀 값**으로 관리합니다. 값 자체를 Git 커밋, 채팅, 스크린샷에 남기지 않습니다.

| 이름 | 역할 | 최소 조건 |
|---|---|---|
| `EVAL_BANK_V4_JSON` | V4 비공개 문항 은행 전체 JSON | 파서 기준 문자열 길이 20~200,000, V4 형식 검사 통과; 배포 용량은 별도 확인 |
| `EVAL_ASSIGNMENT_SECRET` | 회차·학급·번호별 결정적 문항 배정용 비밀값 | 임의 생성한 32자 이상 |

문자열 길이 상한은 등록 가능한 바이트 용량이 아닙니다. Vercel Node.js 런타임은 배포별 환경 변수 이름·값 전체에 64KB 제한을 두므로 다른 변수와 실제 JSON 바이트 크기를 함께 확인해야 합니다. [공식 제한](https://vercel.com/docs/limits#environment-variables), 2026-09-15 확인. 문항 콘텐츠의 별도 비공개 관리 권고와 선택 기준은 [계획 9.2절](EVALUATION_V4_PLAN.md#92-비공개-문항-보관과-다른-pc-접근)을 따릅니다.

비밀값은 비밀번호 관리 도구에서 생성·보관합니다. 같은 회차의 채점 결과를 재현해야 하므로 운영 중에는 `EVAL_ASSIGNMENT_SECRET`을 바꾸지 않습니다. 회차가 완전히 끝나고 보관 정책에 따라 재현이 더 필요 없을 때만, 다음 V4 회차 준비 전에 교체 여부를 결정합니다.

## 다른 PC로 넘기기 전 남은 결정

실제 V4 자료는 아직 작성·등록 전입니다. 공개 Git은 코드·문서 전달에만 사용합니다. 실제 문항·정답 검토 자료의 교사 전용 보관 위치, 다른 PC에서 접근할 계정과 전달 방법은 문항 작성 전에 합의합니다. 특정 PC의 제외 파일이 다른 PC에도 있다고 가정하지 않습니다.

회차별 문항 은행 원본과 배정 비밀값의 보존·버전 관리 방식도 운영 전에 정해야 합니다. 비밀값뿐 아니라 문항 은행의 순서·내용 변경도 기존 회차의 배정·채점 재현에 영향을 줄 수 있습니다. 현재 서버 환경 변수를 덮어쓰는 것만으로 과거 회차 보존이 해결되었다고 간주하지 않습니다. 이는 후속 설계 항목이며 이번 인수인계에서 저장 방식이나 운영 값을 변경하지 않습니다.

## 실제 운영 전 점검 순서

1. 회차별 문항·배정·채점 기준 보존과 현재/보관 회차 복구 설계를 먼저 결정합니다. 보호 위치를 합의한 뒤 교사 전용 장소에서 문항 청사진과 정답·유사 정답·출제 의도를 검토합니다.
2. 위 두 환경 변수를 등록하고, 공개 저장소의 코드·문서에 실제 문항이나 비밀값이 없는지 검색합니다.
3. 테스트 전용 Firebase 또는 사전 합의한 빈 학급에서 학생 1명과 담당 교사 1명으로 시작·답안 저장·제출·교사 검토를 확인합니다.
4. [검증표](EVALUATION_V4_PLAN.md#10-다음-구현에서-사용할-검증표)에 따라 API·Firestore 직접 접근의 권한, 제출 실패·회차 전환, 은행 변경 후 과거 회차 재현·확정 성적 보존을 확인합니다. 모의 API 검사와 에뮬레이터 규칙 검사, 실제 환경 검증은 별도 기록합니다.
5. 소규모 학생·교사 검증 뒤 교실 대표 기기·동시 사용을 확인합니다. 미해결 사항·복구 절차와 결과를 교사가 검토하고 해당 운영 작업을 승인한 뒤에만 새 V4 회차를 운영 대상으로 선택합니다.

현재 기본 평가는 계속 V3으로 준비됩니다. P0 코드와 Firestore 규칙은 운영 배포되었지만, 이 문서만으로 V4가 열리거나 운영 데이터가 바뀌지는 않습니다. V4 회차 선택 화면과 실제 환경 변수 등록·운영 검증은 문항 품질 검토 뒤의 별도 단계입니다.
