## 변경과 의도

- AI 튜터는 우측에 48px 로봇 아이콘만 남깁니다. 마우스 또는 키보드 초점에서 250ms 동안 펼쳐지고, 클릭·터치로 대화창을 엽니다. 열린 동안 버튼을 유지하며 Escape로 닫습니다. 움직임 감소 설정과 펼침 상태의 접근성 속성을 지원합니다.
- 나만의 백지 휴지통을 캔버스 하단 14px로 내립니다. 900px 이하에서는 튜터 아이콘 자리만큼 오른쪽 여백을 확보하고, 600px 이하에서는 실행 도구를 휴지통 위로 분리합니다.
- 교사용 버튼은 Google 로그인·임시 로그인 선택창을 엽니다. 이미 로그인한 교사는 서버의 교사 역할을 확인해 바로 진입합니다. 로그인 실패는 선택창에서 원인에 맞는 한국어 재시도 안내로 표시합니다.
- 임시 로그인은 개인 Google 계정 없이 사용하는 공용 교사 계정입니다. 기술적으로 Firebase 이메일/비밀번호 인증이며 Firebase 익명 인증과 구분합니다. 계정 식별자는 `temporary-teacher@donghyun-algo.firebaseapp.com`이고 비밀번호는 코드·Firestore·브라우저 저장소에 저장하지 않습니다. 브라우저 입력을 Firebase 인증 SDK에 전달하고, 이후 `teachers/{uid}.enabled`를 확인합니다. 클라이언트에서 계정이나 교사 역할을 생성하지 않습니다.
- 교사 인증 상태에서 수행평가 메뉴는 교사용 화면으로 연결됩니다. 같은 탭 새로고침으로 복원된 로그인도 역할을 조회합니다. 진행 중인 학생 평가의 이동 제한은 유지합니다.
- 로그인 취소 시 이전 화면과 메뉴 선택을 유지하고, 늦은 로그인·권한 조회가 다른 화면을 덮지 않게 합니다. 로그인 대기 중에도 창을 닫을 수 있습니다. 새 로그인 후 권한 확인 실패 시 그 로그인을 정리하고, 아직 제출하지 않은 학생이 입장한 창에서는 교사 계정 전환을 막습니다.
- 사용자의 실제 수업 피드백에 따라 나만의 백지에서 `현재 상태로 제출`을 제거했습니다. 당시 답안의 AI 설계 검사 통과 후에만 제출용 이미지 복사·다운로드가 가능합니다. 수정·검사 실패·AI 장애 후에는 다시 검사해야 합니다. 수행평가의 미완성 제출은 유지합니다.

Firebase 인증 방식 참고: [공식 비밀번호 인증 문서](https://firebase.google.com/docs/auth/web/password-auth), 2026-09-13 확인.

## 운영 임시 계정 설정 — 아직 미실행

운영 배포 전에 다음을 수행해야 합니다. 현재 시연 화면의 로그인은 모의 동작입니다.

1. Firebase Authentication에서 이메일/비밀번호 제공자를 활성화합니다.
2. 위 식별자로 계정을 한 번 생성하고 충분히 긴 임의 비밀번호를 관리자에게 전달합니다. 이미 같은 계정이 있다면 관리자 소유인지 확인하고 비밀번호·기존 세션을 관리자 권한으로 재설정한 뒤 사용합니다. 식별자가 같다는 이유만으로 기존 계정에 교사 역할을 부여하지 않습니다.
3. 생성된 UID의 Firestore `teachers/{uid}` 문서에 `enabled: true`를 관리자 권한으로 등록합니다. Firestore 문서만 만드는 것은 로그인 계정 생성이 아닙니다.
4. 실제 임시 로그인·권한 없는 계정 거부·로그아웃·다른 PC 재로그인을 확인합니다. 기존 학생 답안과 교사 계정은 변경하지 않습니다.
5. 임시 계정을 중지할 때는 Auth 사용자 비활성화와 교사 역할 `enabled: false`를 적용합니다. 공용 계정이므로 교사 개인별 조작 구분은 제공하지 않습니다.

추가 자체 인증 서버나 서비스 계정 비밀 키는 도입하지 않습니다. Google 팝업 사용이 어려운 경우의 대체 경로이며, Firebase 연결 자체가 차단된 환경에서의 오프라인 로그인은 지원하지 않습니다.

## 검증

검증 결과는 `tests/results/tutor-login-ui.json`, `tests/results/tutor-entry-regression/browser.json`, `tests/results/workspace-ui.json`, `tests/results/assessment-ui.json`, `tests/results/teacher-controls.json`에 기록합니다. 모든 브라우저 검사는 로컬 Edge 모의 환경이며 실제 Google·Firebase 비밀번호 로그인이나 Solar 호출 검사가 아닙니다.

- 기본/API/인증 25개 통과 (`node --test --test-isolation=none tests/*.test.cjs`). Windows 샌드박스의 자식 프로세스 생성 제한 때문에 동일 프로세스 검사 옵션을 사용했습니다.
- 신규 튜터·로그인 6개, 작업 공간 5개, 수행평가 10개, 교사 운영 8개 통과. 페이지·콘솔 오류 없음.
- 전체 브라우저 24개 통과. 기본 검사와 합쳐 총 78개 사례를 확인했습니다. 기존 PNG 파일 덮어쓰기 잠금으로 인한 실패는 별도 결과 폴더로 해결했고, 창 크기 전환 애니메이션 도중 좌표를 읽던 검사는 전환 완료 후 읽도록 수정했습니다. 최종 검사에서 페이지·콘솔 오류는 없었습니다.
- 튜터 1440→320px의 9개 폭, 휴지통 1440/1024/900/768/390px, 마우스 펼침·키보드 초점·Enter/Escape·움직임 감소·좁은 화면 실제 클릭 지점을 확인했습니다. 1440px 및 390px 결과 이미지를 직접 확인했습니다.
- 기존 검사의 `맞으면` 문구는 현재 코드의 `예`로, 샌드위치 결과 버튼 검사는 실제 샌드위치 화면에서 수행하도록 맞췄습니다. 제출 버튼 조작 검사는 새 정책에 맞게 비활성 표시 확인과 실제 AI 통과 후 제출 검사로 구분했습니다.

일반 실습 제출의 통과 표시는 AI 설계 점검 결과이며 공식 정답 보증이 아닙니다. AI 장애 시 제출은 대기하므로 교사는 연결 복구 후 재검사를 안내해야 합니다.
