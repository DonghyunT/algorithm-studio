# 자유 설계 수행평가와 AI 초벌 검토

## 학생 화면

객관식 두 문항의 질문 길이가 달라도 보기 목록을 같은 높이에 맞춥니다. 보기의 괄호 부연을 모두 제거하여 9번 정답의 `입출력` 설명만 남아 있던 단서도 없앴습니다.

새 회차는 네 고정 주제를 선택하는 대신 자기 문제의 현재 상태·목표 상태·조건을 상단 처방전에 적습니다. 조건은 직접 입력하거나 AI 후보를 선택한 뒤 수정할 수 있습니다. 조건 추천은 일반 실습의 완성 알고리즘 생성과 다른 요청이며 행동 순서·코드·카드를 생성하지 않도록 제한합니다. 학생이 자연어 카드를 직접 작성하는 원칙을 유지합니다. 평가 기준 네 항목도 처방전에 표시합니다.

실행 버튼은 학생 입력으로 한 번의 흐름을 진행합니다. `기온 입력` 같은 입출력 기호에서 값을 받고 수식 조건은 계산하며, 일상 자연어 판단은 학생이 예·아니요를 선택합니다. 반복이 입력 단계로 돌아오면 다시 입력을 받습니다. 여러 검사 입력을 자동 재생하지 않으며 종료 도착은 정답 판정이 아닙니다. 편집·파트 이동·제출 시 진행 중인 실행과 입력 대기를 정리합니다.

## 교사 검토와 점수

사용자 승인 기준 `open-design-v1`: 문제·조건의 명확성, 자연어 알고리즘의 논리성, 자연어와 순서도의 일치, 순서도 구조·동작의 타당성 각 10점. 문장 길이·맞춤법·모든 제어구조 사용 여부를 가점·감점 기준으로 추가하지 않습니다.

교사용 답안 화면에서 제출 후 Solar AI 초벌 채점을 요청합니다. AI는 네 항목의 제안 점수·근거·불확실성을 작성합니다. 교사는 각 점수를 수정할 수 있으며 답안과 점수를 확인했다는 체크 후 별도로 확정합니다. AI를 사용하지 않고 교사가 직접 네 항목에 점수를 입력해도 됩니다.

제안은 확정 점수와 별도로 저장합니다. Part 1·2는 60점 범위에서 자동 계산하고, Part 3·총점은 교사 확정 전까지 채점 대기로 표시합니다. AI 장애를 0점으로 대체하지 않습니다. CSV도 미확정 점수를 채점 대기로 내보내며 확정 후에만 총점을 계산합니다. 교사 확정 내용은 학생 결과에도 반영합니다.

## 서버와 보존

`/api/assessment`는 조건 추천과 교사 검토 요청을 처리합니다. 기존 Solar 모델·비밀 키·Firebase 프로젝트 설정을 사용하며 API별 UID 분당 제한과 공통 일일 사용량을 적용합니다.

채점 요청은 서버에서 교사 역할을 확인하고 Firestore의 현재 회차 제출 답안을 직접 조회합니다. 클라이언트가 보낸 임의 답안이나 프롬프트로 채점하지 않습니다. 모델에는 현재·목표·조건·자연어 카드·기호·연결만 보내며 이름·번호·계정 UID 등 식별 필드는 제외합니다. 학생이 답안 본문에 직접 입력한 개인정보를 자동 식별·삭제하는 기능은 아닙니다.

서버 고정 프롬프트는 점수 구간별 기준, 자료 안의 지시문을 따르지 않는 원칙, 모호함의 명시, 중복 감점 방지와 근거 요구를 포함합니다. 반환 형식과 각 항목의 0~10 정수 범위를 검사하고 합계는 서버에서 계산합니다. 엄격한 프롬프트가 모델 판단의 정확성·일관성이나 지시문 공격의 완전 차단을 보장하지는 않습니다. 교사 확인 단계가 필요합니다.

새 회차는 문항 버전 3을 사용합니다. 이전 버전 1·2의 문항과 기존 점수 기준을 보존합니다. 검토 결과는 회차와 정규화한 답안 스냅샷에 묶으며 다른 답안에 오래된 제안·확정 점수를 적용하지 않습니다. 재시험은 기존 답안과 검토를 보관한 뒤 현재 검토를 초기화합니다. 상세 필드는 [데이터베이스 문서](DATABASE.md)에 기록합니다.

## 로컬 확인 방법과 배포 상태

기존 로컬 미리보기를 새로고침하고 교사용에서 **새 평가 준비**로 회차를 만든 뒤 학생으로 입장합니다. 이전 회차는 고정 주제를 유지합니다. AI 조건 버튼은 로컬 시연 예시임을 명시하며, 실제 Solar 채점은 호출하지 않습니다. 교사용 항목별 직접 입력·확정·학생 점수 반영은 로컬에서 시험할 수 있습니다.

변경 사항은 별도 브랜치의 로컬 구현·검증·커밋 범위입니다. main 병합·원격 푸시·Vercel 배포·운영 Firestore 변경은 수행하지 않았습니다.
