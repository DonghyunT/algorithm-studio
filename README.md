## 수업에서 활용하기

* **문제 추상화**: 맛보기와 워크북으로 현재·목표 상태, 조건, 핵심 요소를 정리합니다.
* **알고리즘 설계**: 샌드위치 로봇 명령을 조립·실행하며 오류를 찾아 수정합니다.
* **순서도 연구소**: 순차 → 선택 → 반복 → 예시 → 나만의 백지 순으로 연습합니다.

단원별 2차시를 기본 흐름으로 삼되 필요한 추수활동을 선택합니다. 일반 실습은 AI 도움과 재실행을 권장하며, 나만의 백지는 현재 답안의 AI 설계 점검을 통과한 뒤 결과물을 내보냅니다. AI 장애에는 재검사를 안내합니다.

수행평가는 연결 누락·실행이 막힌 위치를 안내하며 학생이 입력·분기를 선택해 실행 결과를 자신의 목표와 비교합니다. 모든 자연어를 자동 채점하는 실행기는 아닙니다. 미완성 답안도 제출할 수 있고 추가 설명문이나 힌트 감점을 요구하지 않습니다. 자동 계산은 교사 최종 검토 전 참고값입니다.

## 접속과 운영 환경

교사는 우측 상단 **교사용**에서 로그인합니다. 선생님은 Google 로그인으로 전체 반을 관리하고, 강사님은 **교사 비밀번호 로그인**으로 10·11반을 관리합니다. 운영 강사 비밀번호는 관리자에게 전달받으며 로컬 시연 비밀번호와 다릅니다. 권한은 화면뿐 아니라 서버에서도 담당 반으로 제한합니다.

기본 운영 방향은 **Vercel 배포 주소로 접속 + Firebase 연동**입니다. 학생은 별도 설치 없이 브라우저를 사용합니다. 프런트엔드는 HTML/CSS/Vanilla JS이며 빌드 단계가 없습니다. 서버리스 API와 개발용 검증 도구는 별개입니다.

파일 더블 클릭은 일부 화면을 살펴보는 용도로 취급하며 AI·평가 저장 등 전체 기능을 보장하지 않습니다. Tailwind CDN·외부 SDK 등 네트워크 의존성이 있어 완전 오프라인 앱이 아닙니다. Netlify에 폴더를 올리는 것만으로 Vercel API가 제공되는 것도 아닙니다.

저장소에는 `api/chat.js`, `api/assessment.js`, `api/evaluation.js`와 Firebase 설정·규칙이 있습니다. AI 비밀 키는 서버 환경 변수 `UPSTAGE_API_KEY`로 관리합니다. 운영 배포와 접근 권한의 확인 범위는 배포 기록을 따릅니다. 브라우저 직접 호출용 키 파일을 학생 배포물에 넣지 않아야 하며 `.gitignore`만으로 배포물의 키 보호나 API 접근 제어가 보장되지는 않습니다.

## 수업 준비와 마무리

1. **수업 전**: 배포 주소를 교실 브라우저에서 열고 활동·실행·결과물 내보내기를 확인합니다. 수행평가는 별도 시험용 환경에서 저장·재접속·교사 종료·권한을 검증해야 합니다. 현재 감사 결과만으로 실제 성적 처리의 준비 완료를 선언하지 않습니다.
2. **실습 중**: 학생이 직접 조립·실행하고 도움을 받아 수정하도록 안내합니다. AI 연결 장애와 풀이 오류를 구분합니다.
3. **공유 시**: 결과물 카드를 복사해 띵커보드/패들릿에 붙여넣거나 이미지로 내려받습니다. 카드 내보내기는 외부 게시판 업로드 완료와 다릅니다. 이미지는 편집 가능한 작업 복구 파일이 아닙니다.
4. **평가 제출 확인**: 서버 저장 성공 후 완료 화면을 표시합니다. 실패하면 창을 유지하고 재시도합니다. 마감 후 미전송 답안은 교사 확인이 필요합니다. 일부 실제 저장·제출 검증은 배포 기록에 있으며, 학급 전체 동시 사용과 교실 네트워크 검증은 남아 있습니다.
5. **수업 종료**: 학생 화면과 세션을 종료하고 다음 학생에게 이전 정보가 보이지 않는지 확인합니다. 창 종료가 Firebase 기록 삭제를 뜻하지 않습니다. 다음 차시 이어하기·서버 보관 및 삭제 정책은 미정입니다.

## 문서와 인수인계

새 PC의 Git 받기·Node.js 24·기본 시연·검사 명령은 [인수인계](docs/HANDOFF.md)에 모았습니다. 완료된 작업은 `main`에 통합하며, 다른 PC에서는 최신 `main`을 받은 뒤 목적별 새 작업 브랜치를 만듭니다. 과거 기록은 [인수인계 보존본](docs/HANDOFF_HISTORY_2026-09-15.md)입니다.

### 로컬에서 실제 AI와 임시 교사 체험

`node tools/preview.cjs --ai`를 실행하고 http://127.0.0.1:4174/index.html?demo=1 에 접속합니다. 기본 명령(`node tools/preview.cjs`, 4173)은 실제 AI 없는 시연입니다.

교사용 → 임시 로그인을 선택하고, 실행 시 자동 생성된 `.env.preview.local`의 `LOCAL_TEACHER_PASSWORD=` 오른쪽 값을 입력합니다. 이 파일은 Git과 배포에서 제외되며 새 PC에서는 별도로 생성됩니다. 로컬 계정은 운영 교사 권한을 갖지 않고 학생 자료·평가 저장도 로컬 시연으로 유지됩니다.

실제 AI는 기존 운영 API를 통해 연결하므로 인터넷과 기존 AI 사용량이 필요합니다. 브라우저에 AI 키나 운영 인증 토큰을 전달하지 않습니다. 서버는 이 PC의 127.0.0.1에서만 열리며 AI 호출은 분당 5회·서버 실행당 30회로 제한합니다. 체험을 마치면 실행 터미널에서 Ctrl+C로 종료합니다. [구현·보안·검증 범위](docs/SEMANTIC_REVIEW_LOCAL_PREVIEW.md)를 참고하세요.

* [AGENTS.md](AGENTS.md): 기술·협업 규칙
* [INTENT.md](INTENT.md): 교육 목적과 실습·평가 철학
* [PRD.md](PRD.md): 현재 요구사항·구현 상태·완료 조건·미결정 사항
* [감사 보고서](audit/AUDIT_REPORT.md): 오류 근거와 검증 한계
* [다른 PC 인수인계](docs/HANDOFF.md): clone/pull, 로컬 실행, 별도 로그인과 진행 중 작업

다른 PC 환경이나 새로운 AI 어시스턴트로 작업을 이어갈 때는 Git 원격 저장소의 `현재 운영 브랜치` 최신 커밋을 기준으로 상태를 동기화하며, AI에게 3대 핵심 문서(AGENTS, INTENT, PRD)와 `docs/HANDOFF.md` 정독을 요청하여 컨텍스트를 즉시 복원합니다. 비밀 키는 인수인계 문서나 저장소에 남기지 않습니다.
